# Familiar Characters mobile loading — 27 October 2026

Implemented locally; no public deployment, commit or push. Review at
[English](http://localhost:4173/familiarcharacters/) or
[Japanese](http://localhost:4173/ja/familiarcharacters/).

## Result

Same-seed, cold-cache mobile comparison on the compressed generated package:

| Language | First visible photo, before → after | LCP, before → after | Encoded document + resources, before → after |
| --- | ---: | ---: | ---: |
| EN | 2.43 → 1.97 s | 2.95 → 2.79 s | 1.07 → 0.99 MiB |
| JA | 2.89 → 2.65 s | 17.32 → 3.16 s | 3.24 → 1.17 MiB |

These are medians from three English and two Japanese runs at 393×852 CSS px,
3× DPR, Chrome, 4× CPU slowdown, 150 ms latency and 200,000 bytes/sec download.
The exact same seeded object arrangement, viewport, connection settings, cold
browser/cache, first-visit info sheet, image URLs and display geometry were used
on each side. JavaScript and animation remained enabled. All pages stayed local
and no real analytics requests or form submissions were sent.

This is a controlled local lab comparison, not an on-device Safari or production
Core Web Vitals certification. English LCP is still influenced by the unchanged
entrance/info motion and showed run-to-run variation (2.44–4.10 s after the change,
median 2.79 s). Japanese median LCP fell by about 82%; English first-photo time
fell by about 19%. Early logo FCP was approximately 0.74→0.77 s EN and 0.91→0.99 s
JA; these small early-paint changes are included rather than claiming every
individual timing improved. Real hosting and device results can differ.

## Implementation

- Start the hidden fallback catalog dormant under the existing `finds-js` guard.
  This prevents unused fallback typography from downloading during startup.
  Keep its complete authored HTML, semantic heading, no-JS experience and 4 s
  failure watchdog. The clipped heading uses a system font only while invisible;
  the normal shared type returns automatically in the visible fallback.
- Preserve DOM/map order while queueing visible image requests center first.
  The center gets a high-priority hint; edge images remain automatic. Existing
  overscan, responsive source sizing, native/zoom images and entrance keyframes,
  duration and stagger are unchanged. No image was recompressed or replaced.
- Split the existing OFL Zen Kaku Gothic New faces into on-demand Unicode banks.
  The original Medium/Bold/Black → CSS 400/500/600–700 mapping stays intact.
  Both initially used Japanese faces total 99,860 bytes instead of 2,149,272 bytes
  (95.4% less). Core kana and voicing marks stay together so decomposed input
  shapes identically. Other authored copy and the remaining characters load on
  demand. All original character coverage remains available.
- Declare SC Walla's exact existing Unicode coverage in CSS. This lets Japanese
  font downloads start without waiting for a Latin font to prove a glyph is
  absent. Purchased font binaries are unchanged.
- Deliver only the collection's 363 Japanese UI/catalog translations at startup,
  down from the whole site's dictionary. The translated strings are identical;
  other Japanese pages retain their full dictionary. Generated by the existing
  Japanese build helper, with a runtime/catalog coverage test.
- Cache content-hashed font banks immutably. Existing private noindex settings,
  optional analytics behavior, SEO content and design remain intact.

No new visible UI or design elements were introduced.

product saving, Favorites and info-sheet dismissal passed without runtime errors.
Responsive/interaction proof and screenshots are retained in the ignored folder
`tmp/fc-mobile-performance/`, together with raw before/after timings. The current

## Maintaining the delivery assets

Normal preview/deployment needs only the committed/generated files. For a future
font refresh, first regenerate Japanese pages, then run:

```sh
python3 scripts/build-japanese.py
python3 scripts/build-japanese-fonts.py
python3 scripts/build-preview.py
```

The font helper needs development-only Python `fontTools` and `Brotli`. It retains
original fonts and OFL metadata, verifies the generated glyphs, and writes
`data/japanese-font-build.json`. New text can already use the complete fallback
banks; regenerating the banks optimizes which characters arrive first.

Primary implementation references:
[fontTools subsetting](https://fonttools.readthedocs.io/en/latest/subset/index.html)
and [CSS composite font coverage](https://www.w3.org/TR/css-fonts-4/#composite-fonts).
