## Performance: implemented and measured locally

Generated delivery assets now use one minified, content-hashed stylesheet per
page; local imports and relative URLs preserve their source cascade and paths.
Copied JS is minified with UTF-8 retained. Source styles/scripts remain editable
separately, and no production deployment occurs in the helper. Immutable bundle
cache headers are prepared; the ordinary source preview still works buildlessly.

Lossless 160px image candidates and a closer source-size hint reduce unnecessary
thumbnail downloads, especially on 3× displays. All 107 new candidates exactly
match the expected Lanczos-resized RGBA bytes; originals, crop/color treatment
and larger zoom candidates are preserved. The same 107-photo set is 1,481,340 bytes
at 160px versus 1,978,454 bytes at 192px: **25.1% less**. That is a deterministic file
comparison, not a claim that every visit downloads 25.1% less overall.

Lighthouse 13.5 mobile lab, cold browser, simulated slow mobile network/CPU:

| Local delivery | Performance | FCP | LCP | TBT | CLS |
| --- | ---: | ---: | ---: | ---: | ---: |
| Home: original uncompressed source | 77 | 3.0s | 4.7s | 0ms | 0.001 |
| Home: compressed source | 86 | 2.3s | 3.7s | 0ms | 0.001 |
| Home: compressed optimized package | 88 | 1.8s | 3.7s | 0ms | 0.001 |
| Collection: final package | 75 | 2.6s | 5.6s | 0ms | 0 |

The Home comparison separates compression from bundling. Collection selection
randomizes, so its repeated lab runs are not a controlled same-photo A/B test.
Its latest measured total was 695 KiB versus 825 KiB in an earlier randomized run;
use the deterministic thumbnail comparison above for an exact saving claim.
The intentional entrance animation and photo network load still affect LCP.
**Collection mobile LCP still has room to improve; no production Core Web Vitals
pass is claimed.** These are local lab measurements, not real public-host or
field data. Raw results, settings and screenshots are in the ignored proof folder.
